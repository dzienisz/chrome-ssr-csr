How is this page rendered?

Open any site and get the answer in one click — plus the evidence behind it, where the HTML was produced, and exactly which parts of the page JavaScript built.

1Pin it to your toolbar

Browsers hide new extensions behind the puzzle icon. Pin it so the report is always one click away.

Click the puzzle icon → find CSR vs SSR Detector → click the pin

Not pinned yet

2Read the verdict

The toolbar badge gives you the headline; the popup explains how it got there.

SSR

The content arrived in the initial HTML. Good for search engines and first paint.

CSR

The browser built the page from JavaScript. Typical of app-like single-page sites.

MIX

Some of the page came from the server, the rest was hydrated or fetched afterwards.

3Go deeper when you need to

  • Evidence — every signal that moved the verdict, with the points it contributed.
  • Delivery — whether the HTML was built at build time, served from a CDN cache, or rendered for this request, read straight from the response headers.
  • Regions — which parts of the page the server sent and which ones JavaScript filled in.
  • DevTools panel — the same report, full width, re-running on every navigation. Look for “Rendering” in DevTools.

Your privacy

Anonymous statistics — domain, render type, performance metrics, never full URLs or page content — help tune detection against the real web. Response headers and the region breakdown never leave your device. Opt out any time.
